🏗️ Dual-Store Architecture & Dimensional Model

Design rationale and entity relationships connecting the MongoDB Landing Zone to the PostgreSQL Star Schema.

Dual-Store Hybrid Lakehouse Rationale

1. MongoDB 7.0 (Landing Lake): Preserves 100% of untampered raw survey submissions with cryptographic SHA-256 hashes, batch identifiers, and payload metadata. Schema-flexible JSON handles unexpected column variations between election cycles without silent rejection.

2. Transform & Clean Engine: Resolves Unicode mojibake, unifies ambiguous null tokens, executes RapidFuzz token sort matching for states and parties, and calculates IQR outlier boundaries.

3. PostgreSQL 16 (Star Schema DW): Idempotent upserts (INSERT ... ON CONFLICT DO UPDATE) load normalized dimensions and facts. Indexed with B-Tree, partial, and GIN structures for high-concurrency window function analytics.

Dimensional Star Schema Entities
  • warehouse.fact_responses (80,591 rows): Central fact table with surrogate keys, monthly incomes, survey ratings (1-5), and quality scores.
  • warehouse.fact_response_choices (136,062 rows): Normalized bridge table exploding multi-select choices without string splitting.
  • warehouse.dim_respondent (71,392 rows): Deduplicated respondent natural keys, gender, and age brackets.
  • warehouse.dim_geography (66 rows): Canonical states, macro-regions (North, South, East, West), and zones.
